# Agent Lightning Framework
## Overview and Core Innovation
- Enables Reinforcement Learning (RL)-based training of LLMs for ANY AI agent
- Achieves complete decoupling between agent execution and RL training
- Allows seamless integration with existing agents with almost ZERO code modifications
- Addresses limitations of LLMs in complex real-world tasks
- RL benefits
 - Optimizes agents using outcome-based reward signals
 - Enables learning desirable behaviors directly from environment feedback
- Challenges solved by Agent Lightning
 - Existing RL methods tailored for static, single-call tasks
 - Agents exhibit complexity (multiple LLM invocations, tool interaction) and diversity
## Foundational Modeling
- Formulation of Agent Execution as Markov Decision Process (MDP)
 - State: Snapshot of agent execution (e.g., semantic variable values)
 - Action: Output generated by the policy LLM
 - Policy LLM decision-making modeled as Partially Observable MDP (POMDP)
- Unified Data Interface
 - Agent trajectories structured as sequences of transitions
 - Transition components
  - Current state (LLM input)
  - Action (LLM output)
  - Reward
 - Abstracts away orchestration logic
 - Captures all state changes (including non-LLM components)
- Reward Definition
 - Scalar rewards measure task completion quality
 - Intermediate rewards (e.g., successful tool invocation status)
 - Final reward (typically assesses overall task success)
## LightningRL Algorithm
- Hierarchical RL (HRL) method specifically designed for agent training
- Bridges single-turn RL methods to multi-turn agent scenarios
- Two-step mechanism
 - Step 1: Credit Assignment Module allocates episode-level return (R) across actions
 - Step 2: Existing single-turn RL algorithms decompose returns across tokens
- Advantages over Masking-based Approaches
 - Enables highly flexible context construction (e.g., structured prompts)
 - More robust and scalable implementation
 - Alleviates issues of accumulative context and excessively long sequences
 - Eliminates the need for custom masking strategies
- Supports selective optimization of multiple agents simultaneously
## System Design
- Training-Agent Disaggregation (TA Disaggregation) Architecture
 - Achieves clean separation between RL training and agent execution
 - Establishes mutual independence between trainer and agent
 - Allows compute-intensive LLM generation to be managed by the RL framework
 - Components
  - Lightning Server (Controller/Trainer)
   - Manages RL training process
   - Exposes OpenAI-like API of updated model
   - Orchestrates task batches
  - Lightning Client (Agent Runtime/Rollout)
   - Handles communication and data collection
   - Manages agent execution
   - Supports data parallelism (intra-node and inter-node)
- Agent Runtime Features
 - Data Capture without Code Modification
  - OpenTelemetry tracing capabilities
  - Basic tracing via OpenAI-like API endpoint
 - Automatic Intermediate Rewarding (AIR)
  - Converts system monitoring data (e.g., tool call return statuses) into intermediate rewards
 - Error Handling and Robustness
## Application and Validation
- Demonstrates continuous and stable performance enhancement
- Example Tasks
 - Text-to-SQL via LangChain
  - Dataset: Spider
  - Tool: SQL executor
  - Scenario: Multi-agent system (selective optimization of two agents)
 - Retrieval-Augmented Generation (RAG) via OpenAI Agents SDK
  - Dataset: MuSiQue (multi-hop QA)
  - Tool: Wikipedia retriever
 - Math QA with Tool Usage via AutoGen
  - Dataset: Calc-X
  - Tool: Calculator
## Comparison to Related Work
- Decoupling vs Tight Coupling
 - Existing large-scale RL systems require rebuilding agents inside the training system
 - Agent Lightning integrates seamlessly without requiring agent code migration
- Transition-based Modeling vs Concatenation/Masking
 - Supports broader agent architectures and dynamic workflows
 - Relieves context length constraints
 - Simplifies implementation by eliminating custom masking strategies
## Future Work
- Support for More Optimization Methods (beyond RL)
 - Leveraging Component of Interest (CoI) concept (e.g., prompt optimization)
- Improvement on RL Algorithms
 - Focusing on long-horizon credit assignment and exploration
- Advancements in RL System Infrastructure
 - Further disaggregation of trainer, rollout, and agent workflows
- Efficient Serving
 - Exploring LLM-friendly abstraction (e.g., Parrot)
 - Long-context acceleration techniques (e.g., sparse computing)
