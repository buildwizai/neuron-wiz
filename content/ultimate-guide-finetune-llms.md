# The Ultimate Guide to Fine-Tuning LLMs
## Introduction
- Background of Large Language Models (LLMs)
    - Significant leap in computational systems
    - Leverages Transformer architectures (GPT-3, GPT-4)
    - Key advancements: in-context learning, Reinforcement Learning from Human Feedback (RLHF)
- Historical Development and Key Milestones
    - Evolution from Statistical Language Models (SLMs) to LLMs
- Evolution from Traditional NLP Models to State-of-the-Art LLMs
    - Statistical Language Models (SLMs)
    - Neural Language Models (NLMs)
    - Pre-trained Language Models (PLMs)
    - Large Language Models (LLMs)
- What is Fine-Tuning?
    - Uses a pre-trained model as a foundation
    - Further training on smaller, domain-specific dataset
    - Enhances performance on specific tasks with reduced data and computational requirements
- Types of LLM Fine-Tuning
    - Unsupervised Fine-Tuning (no labelled data)
    - Supervised Fine-Tuning (SFT) (labelled data)
    - Instruction Fine-Tuning via Prompt Engineering (natural language instructions)
- Pre-training vs Fine-tuning
    - Pre-training: Build general linguistic knowledge, high computational cost, extensive data
    - Fine-tuning: Specialise model for specific tasks, lower cost, smaller data
- Importance of Fine-Tuning LLMs
    - Transfer Learning
    - Reduced Data Requirements
    - Improved Generalisation
    - Efficient Model Deployment
    - Adaptability to Various Tasks
    - Domain-Specific Performance
    - Faster Convergence
- Retrieval Augmented Generation (RAG)
    - Incorporates external data into the prompt
    - Avoids fine-tuning costs and time
    - Traditional RAG Pipeline and Steps
        - Data Indexing
        - Input Query Processing
        - Searching and Ranking
        - Prompt Augmentation
        - Response Generation
    - Benefits of Using RAG
        - Up-to-Date and Accurate Responses
        - Reducing Inaccurate Responses
        - Domain-Specific Responses
        - Efficiency and Cost-Effectiveness
    - Challenges and Considerations in Serving RAG
        - User Experience, Cost Efficiency, Accuracy, Recency and Relevance, Business Context Awareness, Service Scalability, Security and Governance
    - Considerations for Choosing Between RAG and Fine-Tuning
        - RAG for external data, dynamic data, transparency
        - Fine-tuning for behavior, writing style, ample labelled data
- Objectives of the Report
    - Comprehensive analysis of fine-tuning techniques
    - Address critical questions, outline structured process

- Parameter-Efficient Fine-Tuning (PEFT) Techniques
    - Reduces computational and storage costs, mitigates catastrophic forgetting
    - Adapters (additional trainable parameters)
    - Low-Rank Adaptation (LoRA)
        - Freezes original weights, applies changes to separate low-rank weights
        - Benefits: Parameter Efficiency, Efficient Storage, Reduced Computational Load, Lower Memory Footprint, Flexibility, Compatibility, Comparable Results, Task-Specific Adaptation, Avoiding Overfitting
        - Limitations: Fine-tuning Scope, Hyperparameter Optimisation, Ongoing Research
    - QLoRA (Quantised LoRA)
        - Greater memory efficiency by quantising weights to 4-bit precision
        - Quantises LoRA adapters from 8-bit to 4-bit
        - Maintains performance comparable to 16-bit fine-tuning
    - Weight-Decomposed Low-Rank Adaptation (DoRA)
        - Decomposes weights into magnitude and directional components
        - Leverages LoRA for directional updates
        - Benefits: Enhanced Learning Capacity, Efficient Fine-Tuning, No Additional Inference Latency, Superior Performance, Versatility Across Backbones, Innovative Analysis
        - Comparison with LoRA: DoRA separates magnitude and direction components for distinct updates
    - Fine-Tuning with Multiple Adapters
        - Consolidates multiple adapters into a unified multi-task adapter
        - Methods: Concatenation, Linear Combination, SVD
        - Allows adjusting adapter behavior by prioritizing influence
- Half Fine Tuning (HFT)
    - Balances retention of foundational knowledge with acquisition of new skills
    - Freezes half of parameters, updates other half during each round
    - Benefits: Recovery of Pre-Trained Knowledge, Enhanced Performance, Robustness, Simplicity and Scalability, Versatility
    - Comparison with LoRA: HFT does not alter model architecture, LoRA introduces new low-rank matrices
- Lamini Memory Tuning
    - Specialised approach to fine-tuning LLMs targeting reduction of hallucinations
    - Lamini-1 Model Architecture: Massive Mixture of Memory Experts (MoME)
    - Systems Optimisations for Banishing Hallucinations
- Mixture of Experts (MoE)
    - Divides computation into several specialised subnetworks ("experts")
    - Mixtral 8x7B Architecture and Performance (Sparse MoE, router selects two experts per token)
- Mixture of Agents (MoA)
    - Leverages collective expertise of multiple LLM agents in a layered architecture
    - Methodology: Classification (Proposers, Aggregators), diverse model outputs
    - Analogy with MoE: MoA operates at the model level via prompt-based interactions
    - What makes MoA works well? Superior Performance, Effective Incorporation of Proposals, Influence of Model Diversity and Proposer Count, Model Specialisation
- Proximal Policy Optimisation (PPO)
    - Reinforcement learning algorithm for training agents
    - Uses a "surrogate" objective function with clipping mechanism
    - Benefits: Stability, Ease of Implementation, Sample Efficiency
    - Limitations: Complexity and Computational Cost, Hyperparameter Sensitivity, Stability and Convergence Issues, Reward Signal Dependence
- Direct Preference Optimisation (DPO)
    - Streamlined approach to aligning language models with human preferences
    - Bypasses complexity of RLHF
    - Benefits: Direct Alignment with Human Preferences, Minimised Dependence on Proxy Objectives, Enhanced Performance on Subjective Tasks
    - Best Practices: High-Quality Preference Data, Optimal Beta Value, Hyperparameter Tuning, Evaluation on Target Tasks, Ethical Considerations
    - DPO vs PPO for LLM Alignment: Study investigates efficacy of reward-based (PPO) and reward-free (DPO) methods
- Odds-Ratio Preference Optimization (ORPO)
    - Novel approach to align LM output with desired responses
    - Introduces a penalisation mechanism for undesirable outputs
    - Monolithic, no reference model needed
- Pruning LLMs
    - Eliminating unnecessary or redundant components to reduce size and complexity
    - Techniques: Weight Pruning, Unit Pruning, Filter Pruning
    - When to Prune AI Models? Pre-Training Pruning, Post-Training Pruning, Dynamic Pruning
    - Benefits of Pruning: Reduced Size and Complexity, Improved Efficiency and Performance, Enhanced Generalisation and Accuracy
    - Challenges of Pruning: Balance Size Reduction/Performance, Choosing Appropriate Techniques, Evaluation and Validation

## Open Challenges and Research Directions
- Scalability Issues
    - Challenges in Scaling Fine-Tuning Processes: Computational Resources, Memory Requirements, Data Volume, Throughput and Bottlenecks, Efficient Use of Resources
    - Research Directions for Scalable Solutions
        - Advanced PEFT Techniques and Sparse Fine-Tuning (LoRA, QLoRA, SpIEL)
        - Data Efficient Fine-Tuning (DEFT)
            - Optimises fine-tuning by focusing on critical data samples
            - Key Components: High Accuracy Through Influence Score, High Efficiency Through Effort Score and Surrogate Models
            - Practical Implications: Few-Shot Fine-Tuning, Reducing Computational Costs
            - Future Directions: DEALRec, limited context window
        - Hardware and Algorithm Co-Design (Custom Accelerators, Algorithmic Optimisation, NVIDIA TensorRT)
